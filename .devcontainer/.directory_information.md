# `.devcontainer`

Devcontainer definition for super_projects.

| Path | Role |
|------|------|
| `Dockerfile` | Image build (tools, desktop/VNC, Chrome, mise, CLIs) |
| `compose.yaml` | `devcontainer` service, `localhost_forward_proxy` sidecar, named volumes. Bind mounts and project identity are not interpolated here. |
| `compose.generated.yaml` | Written by `initializeCommand` (gitignored). Literal host bind paths, hostname, `HOST_WORKSPACE_DIR`, and `SUPER_PROJECTS_NAME` so a parent process environment cannot override them. Listed after `compose.yaml` in `devcontainer.json`. |
| `devcontainer.json` | IDE/CLI integration; `initializeCommand` / `postStartCommand` |
| `scripts/` | Helpers by invocation site (`dockerfile/`, `shell/`, `localhost_forward_proxy/`) — see `scripts/.directory_information.md` |
| `persist/` | Dual-mount shortcuts + README for named-volume state (data lives in Docker volumes) |
| `.env.namespace_override.example` | Tracked copy-me template (`SUPER_PROJECTS_NAME=super_projects`). Copy to `.env.namespace_override`. |
| `.env.namespace_override` | User override (gitignored, never regenerated). Source of truth for `${SUPER_PROJECTS_NAME}`; else it defaults to super_projects. |
| `.env` | Generated on the host by `initializeCommand` (gitignored, overwritten every initialize); bind-mount vars plus `SUPER_PROJECTS_NAME` and mirrored `COMPOSE_PROJECT_NAME`. Users do not edit this file. |
