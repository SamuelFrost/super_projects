# `.devcontainer`

Devcontainer definition for super_projects.

| Path | Role |
|------|------|
| `Dockerfile` | Image build (tools, desktop/VNC, Chrome, mise, CLIs) |
| `compose.yaml` | Parent `devcontainer`, `localhost_forward_proxy` sidecar, named volumes, host agent + `known_hosts` mounts |
| `devcontainer.json` | IDE/CLI integration; `initializeCommand` / `postStartCommand` |
| `localhost-forwards.md` | User-facing `http://localhost:<port>` for workspace Compose apps; internals in `scripts/localhost_forward_proxy/.directory_information.md` |
| `scripts/` | Helpers by invocation site (`dockerfile/`, `shell/`, `localhost_forward_proxy/`) — see `scripts/.directory_information.md` |
| `persist/` | Dual-mount shortcuts + README for named-volume state (data lives in Docker volumes) |
| `.env.namespace_override.example` | Tracked copy-me template (`SUPER_PROJECTS_NAME=super_projects`, `SUPER_PROJECTS_WORKDIR=workspaces`). Copy to `.env.namespace_override`. |
| `.env.namespace_override` | User override (gitignored, never regenerated). Source of truth for `${SUPER_PROJECTS_NAME}` and `${SUPER_PROJECTS_WORKDIR}`; else they default to super_projects and workspaces respectively. |
| `.env` | Generated on the host by `initializeCommand` (gitignored, overwritten every initialize); bind-mount vars plus `SUPER_PROJECTS_NAME`, mirrored `COMPOSE_PROJECT_NAME`, and `SUPER_PROJECTS_WORKDIR`. Users do not edit the name or workdir here. |
