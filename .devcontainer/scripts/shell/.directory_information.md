# `.devcontainer/scripts/shell`

Shell scripts under the workspace bind mount (`/${SUPER_PROJECTS_WORKDIR}/.devcontainer/scripts/shell/...`). They are not `COPY`’d into the image, so edits apply without rebuilding.

| Script | Used by | Purpose |
|--------|---------|---------|
| `initializeCommand.sh` | `devcontainer.json` `initializeCommand` (host, before container start) | Run host init steps: ssh-agent, `.devcontainer/.env`, persist dir stubs |
| `ensure-host-ssh-agent` | `initializeCommand.sh` | Ensure host ssh-agent; reads `${SUPER_PROJECTS_NAME}` from `.env.namespace_override` for the socket filename; write `.devcontainer/.selected-ssh-agent.env` (bridge file parsed by `write-devcontainer-env`, not sourced) |
| `write-devcontainer-env` | `initializeCommand.sh` | Write `.devcontainer/.env` (bind-mount vars plus `SUPER_PROJECTS_NAME` and `SUPER_PROJECTS_WORKDIR` from `.env.namespace_override`, and mirrored `COMPOSE_PROJECT_NAME`) |
| `refresh-docker-desktop-ssh-relay` | `initializeCommand.sh` (after `write-devcontainer-env`) | Docker Desktop on WSL2: one-shot `docker run` to recreate the stale bind-mount relay for `HOST_SSH_AUTH_SOCK` |
| `mise-shell-init.sh` | Image `~/.bashrc` (interactive bash) | Prefer mise shims and activate mise |

Do not require developers to run `initializeCommand.sh` manually; VS Code, Cursor, and `devcontainer up` invoke it automatically.
