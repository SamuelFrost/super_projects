# `.devcontainer/lllm`

Local Google Agent Development Kit package for the `lllm` command. The package
connects the ADK app in `agent.py` to the Ollama service configured by the
devcontainer, then renders the ADK event stream for terminal use.

The shell entrypoint is `/usr/local/bin/lllm`. For normal prompts it runs:

```sh
PYTHONPATH=/workspaces/.devcontainer python -m lllm.cli
```

`lllm web` is handled by the shell entrypoint instead and starts the ADK web UI.

| Path | Role |
|------|------|
| `agent.py` | ADK composition root: model, root agent, browser sub-agent, files sub-agent, tools, and `app`. This is the agent definition. |
| `adk_runtime.py` | Creates an `InMemoryRunner`, creates an ADK session, and exposes `AdkSession.stream_events(...)`. Iterating that stream is what calls `runner.run_async(...)`. |
| `cli.py` | Argument parsing, model preload, prompt loop, timeout handling, interrupt exit codes, and wiring between runtime and renderer. |
| `ollama.py` | Checks whether `GEMMA_MODEL` is already loaded in Ollama and loads it before the timed ADK turn when needed. |
| `output_channels.py` | Parses and validates `--outputChannels`, resolves per-agent channel visibility, and validates agent names against the live agent tree. |
| `output_writer.py` | Converts ADK `Event` objects into streamed text, buffered text, or JSON output. |
| `__init__.py` | Re-exports `app` and `root_agent` from `agent.py`. |

## Invocation Flow

For a normal one-shot prompt:

1. `cli.py` parses arguments.
2. `ollama.ensure_model_loaded()` loads `GEMMA_MODEL` if Ollama is cold.
3. `AgentOutputVisibility` resolves the channel rules from `--outputChannels`.
4. `AdkSession.create(adk_app, user_id="user")` creates an ADK runner and session.
5. `session.stream_events(prompt, ADK_SSE_RUN_CONFIG)` calls ADK:

   ```python
   runner.run_async(
       user_id=user_id,
       session_id=session_id,
       new_message=types.UserContent(prompt),
       run_config=RunConfig(streaming_mode=StreamingMode.SSE),
   )
   ```

6. `AdkEventRenderer.consume(event)` prints the selected parts of each ADK event.
7. `AdkEventRenderer.finish()` flushes final newlines, buffered text, or JSON.

## Agents

The current author names used by output filtering are:

| Agent | Role |
|-------|------|
| `lllm` | Root coordinator. User prompts are authored here. Root answers are printed unlabeled on stdout by default. |
| `browser_agent` | Browser specialist using Chrome DevTools tools. |
| `files_agent` | Workspace file specialist using list, search, read, edit, and write file tools. |

Sub-agent requests are treated as the callee's `prompt`. For example, a root
tool call to `files_agent` with a `request` argument is rendered as a
`files_agent` prompt, not as a root `tool_calls` line.

## CLI Options

| Option | Behavior |
|--------|----------|
| `query ...` | Runs one prompt and exits. With no query, `lllm` starts a REPL until `exit`, `quit`, EOF, or ctrl+c. |
| `--outputChannels JSON` | Selects which information is printed for each agent. See below. |
| `--stderr` | Sends trace information to stderr while the root answer remains on stdout. Trace information includes thinking, tool lines, sub-agent prompts, and sub-agent responses. Ignored by `--json`. |
| `--no-stream` | Buffers selected text and prints the turn when ADK finishes. Useful for cleaner captured output, less useful for observing a long run. |
| `--json` | Prints one JSON object on stdout for the selected channels. This buffers until the turn finishes and ignores the stderr split. |
| `--timeout SECONDS` | Times out the ADK turn after this many seconds and exits 124. Model preload happens before this timer. |

Ctrl+c exits 130 after closing the ADK runner.

## `--outputChannels`

`--outputChannels` is one shell-quoted JSON object. It changes terminal
presentation only; it does not change ADK, the model request, tool availability,
or sub-agent delegation.

Top-level keys:

| Key | Meaning |
|-----|---------|
| `defaults` | Channel overrides for every agent, including the root. |
| `sub_agent_defaults` | Channel overrides for agents under the root. Applies after `defaults`. |
| `agent_overrides` | List of targeted overrides. Each entry has `target_agents` plus channel booleans. Later entries win for keys they set. |

Channel keys:

| Channel | Meaning |
|---------|---------|
| `thinking` | Model thinking text. |
| `answer` | Final or streamed answer text. Root answers are unlabeled; sub-agent answers are labeled like `[files_agent response]`. |
| `tool_calls` | Tool names such as `[ReadFile]`, `[new_page]`, or `[take_snapshot]`. A sub-agent delegation is not printed here; it is the callee's `prompt`. |
| `tool_results` | Raw tool result payload text. This can be large. It is off by default. |
| `prompt` | User prompt for the root, or delegated request for a sub-agent. Root prompt is off by default; sub-agent prompts are on by default. |

Built-in defaults:

| Agent group | `thinking` | `answer` | `tool_calls` | `tool_results` | `prompt` |
|-------------|------------|----------|--------------|----------------|----------|
| Root agent | true | true | true | false | false |
| Sub-agents | true | true | true | false | true |

Resolution order:

1. Built-in root defaults.
2. Built-in sub-agent prompt default, for sub-agents only.
3. User `defaults`.
4. User `sub_agent_defaults`, for sub-agents only.
5. User `agent_overrides`, in list order.

Omitted keys keep the value from the layer below. Values must be JSON booleans
`true` or `false`, not strings like `"true"`.

### Examples

Hide thinking everywhere:

```sh
lllm --outputChannels='{"defaults":{"thinking":false}}' "Summarize example.com."
```

Show only the root answer:

```sh
lllm --outputChannels='{"defaults":{"thinking":false,"answer":false,"tool_calls":false,"tool_results":false,"prompt":false},"agent_overrides":[{"target_agents":["lllm"],"answer":true}]}' "Visit example.com and report the title."
```

Hide sub-agent tool names but show raw file results:

```sh
lllm --outputChannels='{"sub_agent_defaults":{"tool_calls":false},"agent_overrides":[{"target_agents":["files_agent"],"tool_results":true}]}' "Read the first line of /workspaces/README.md."
```

Send trace information to stderr so stdout only contains the root answer:

```sh
lllm --stderr "Visit example.com and report the title."
```

Emit JSON for selected channels:

```sh
lllm --json --outputChannels='{"defaults":{"thinking":false},"sub_agent_defaults":{"tool_results":true}}' "Read the first line of /workspaces/README.md."
```

Invalid examples fail before a model call:

```sh
lllm --outputChannels='{"defaults":{"prompt":"true"}}' "ping"
lllm --outputChannels='{"agent_overrides":[{"target_agents":["file_agent"],"answer":true}]}' "ping"
```

The first fails because `"true"` is a string, not a JSON boolean. The second
fails because the live agent name is `files_agent`.

## Output Labels

Common terminal labels:

| Label | Meaning |
|-------|---------|
| `[files_agent]` | Delegated request sent to `files_agent`. |
| `[files_agent response]` | Answer produced by `files_agent`. |
| `[browser_agent thinking]` | Thinking text authored by `browser_agent`. |
| `[ReadFile]` | Tool call name. |
| `[ReadFile result]` | Tool result text when `tool_results` is enabled. |
| `[lllm prompt]` | Root user prompt when root `prompt` is enabled. |

The root answer is intentionally unlabeled so command substitution and piping can
consume it without stripping a prefix.

## Model Loading

The command reads `GEMMA_MODEL`, `OLLAMA_HOST`, and `OLLAMA_KEEP_ALIVE` from the
environment. If `GEMMA_MODEL` is not already listed by Ollama's `/api/ps`,
`ollama.py` sends a small `/api/generate` request before the ADK turn starts and
prints:

```text
lllm: loading <model>
```

This preload is outside `--timeout`, because a cold model can spend a long time
loading weights before producing any ADK events.

## Development Notes

- Keep `agent.py` focused on the ADK app definition. Output policy belongs in
  `output_channels.py` and `output_writer.py`.
- Keep ADK runtime calls visible in `adk_runtime.py`; avoid hiding
  `runner.run_async(...)` behind additional layers unless there is a clear need.
- Add new output channels by updating `CHANNEL_NAMES`, defaults, renderer
  collection, text rendering, and JSON rendering together.
- Validate new agent-targeted options against the live agent tree so typos fail
  before the model starts.
