# `.devcontainer`

Devcontainer definition for super_projects.

| Path | Role |
|------|------|
| `Dockerfile` | Image build (tools, desktop/VNC, Chrome, mise, CLIs) |
| `compose.yaml` | Service, named volumes, host agent + `known_hosts` mounts, startup command. Interpolates `${SUPER_PROJECTS_NAME}` for project name, hostname, network, and ssh-agent socket fallback, and `${SUPER_PROJECTS_WORKDIR}` for the container workspace path (default `workspaces`). Always invoke Compose with `--project-directory .devcontainer` so generated `.env` is loaded. |
| `devcontainer.json` | IDE/CLI integration; `initializeCommand` / `postStartCommand`. `"name"` is the IDE label (`super_projects`), not the Compose project. `"workspaceFolder"` must match `/${SUPER_PROJECTS_WORKDIR}` (JSON cannot interpolate the override). |
| `scripts/` | Helpers by invocation site (`dockerfile/`, `shell/`) — see `scripts/.directory_information.md` |
| `persist/` | Dual-mount shortcuts + README for named-volume state (data lives in Docker volumes) |
| `.env.namespace_override.example` | Tracked copy-me template (`SUPER_PROJECTS_NAME=super_projects`, `SUPER_PROJECTS_WORKDIR=workspaces`). Copy to `.env.namespace_override`. |
| `.env.namespace_override` | User override (gitignored, never regenerated). Source of truth for `${SUPER_PROJECTS_NAME}` and `${SUPER_PROJECTS_WORKDIR}`. Omitting it silently keeps `super_projects` / `workspaces`. |
| `.env` | Generated on the host by `initializeCommand` (gitignored, overwritten every initialize); bind-mount vars plus `SUPER_PROJECTS_NAME`, mirrored `COMPOSE_PROJECT_NAME`, and `SUPER_PROJECTS_WORKDIR`. Users do not edit the name or workdir here. |

Compose interpolates from generated `.env` (and the process environment), not from `.env.namespace_override`. If `.env` is missing or not loaded, yaml defaults to `super_projects`.
