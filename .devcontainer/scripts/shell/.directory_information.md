# `.devcontainer/scripts/shell`

Shell scripts under the workspace bind mount (`/workspaces/.devcontainer/scripts/shell/...`). They are not `COPY`’d into the image, so edits apply without rebuilding.

| Script | Used by | Purpose |
|--------|---------|---------|
| `initializeCommand.sh` | `devcontainer.json` `initializeCommand` (host, before container start) | Run host init steps: ssh-agent, `.devcontainer/.env`, persist dir stubs |
| `devcontainer-env-lib.sh` | Sourced by `ensure-host-ssh-agent` and `write-devcontainer-env` | Shared `env_file_var` (CRLF-safe) and `resolve_super_projects_name` (reads `.env.namespace_override`) |
| `ensure-host-ssh-agent` | `initializeCommand.sh` | Ensure host ssh-agent; socket filename uses `${SUPER_PROJECTS_NAME}` from the override file (not generated `.env`); write `.devcontainer/.selected-ssh-agent.env` (bridge file parsed by `write-devcontainer-env`, not sourced) |
| `write-devcontainer-env` | `initializeCommand.sh` | Write `.devcontainer/.env` (bind-mount vars plus `SUPER_PROJECTS_NAME` and mirrored `COMPOSE_PROJECT_NAME`) |
| `exec-in-devcontainer` | MCP configs (`sh` + this script; locates repo from `$0`) | `docker compose -f .devcontainer/compose.yaml --project-directory .devcontainer exec -T devcontainer` — no hardcoded `${SUPER_PROJECTS_NAME}-devcontainer-1` |
| `refresh-docker-desktop-ssh-relay` | `initializeCommand.sh` (after `write-devcontainer-env`) | Docker Desktop on WSL2: one-shot `docker run` to recreate the stale bind-mount relay for `HOST_SSH_AUTH_SOCK` |
| `mise-shell-init.sh` | Image `~/.bashrc` (interactive bash) | Prefer mise shims and activate mise |

Do not require developers to run `initializeCommand.sh` manually; VS Code, Cursor, and `devcontainer up` invoke it automatically.
