# `.devcontainer/lllm`

Local Google Agent Development Kit package for the `lllm` command. The package
connects the ADK app in `agent.py` to the Ollama service configured by the
devcontainer, then renders the ADK event stream for terminal use.

The shell entrypoint is `/usr/local/bin/lllm`. For normal prompts it runs:

```sh
PYTHONPATH=/workspaces/.devcontainer python -m lllm.cli
```

`lllm web` runs `python -m lllm.web`. That starts the ADK web UI with the prefixed app names (`lllm_default_agent`, `lllm_browser_agent`, `lllm_files_agent`) and the same `.adk/session.db` file. The image copies `/usr/local/bin/lllm` at build time; after changing that script, copy it into the container or rebuild so `lllm web` is not still stock `adk web`.

| Path | Role |
|------|------|
| `agent.py` | ADK composition root: model, root agent, browser sub-agent, files sub-agent, tools, instructions, and `app`. It wires callbacks and does not rewrite tool results or stop a turn. |
| `runtime_modifiers/tool_results.py` | Rewrites tool results before the model or the transcript reads them. Truncated percent-encoded URLs are cut and marked. Long `list_pages` addresses are stored as callback tokens. |
| `runtime_modifiers/turn_guards.py` | Decides when a turn stops because the context window, a repeated tool result, or a repeated reply leaves no room to continue. These callbacks change the next model request. |
| `tools/callback_tokens.py` | Stores text for a turn behind a short token, previews it, and expands it when a tool argument or the root answer needs the text. |
| `adk_runtime.py` | Creates a `Runner` backed by the shared SQLite session database, creates or resumes a session, and exposes `AdkSession.stream_events(...)`. Iterating that stream is what calls `runner.run_async(...)`. |
| `session_store.py` | Resolves the CLI output directory and the shared `.adk/session.db` path. |
| `cli/cli_config.py` | Argument parsing, model preload, prompt loop, timeout handling, interrupt exit codes, and wiring between runtime and renderer. |
| `cli/output_writer.py` | Converts ADK `Event` objects into streamed text, buffered text, or JSON output. Tool results are printed after `runtime_modifiers/tool_results.py` rewrites them, and root answers expand callback tokens. |
| `cli/__main__.py` | Entry point for `python -m lllm.cli`. Applies `--hide-experimental-warnings` before importing `cli_config.py`, then runs `main`. |
| `web.py` | ADK web UI. Lists `named_apps()` and opens the shared SQLite session database. |
| `web_output.py` | Frames streamed SSE records and expands callback placeholders across model text deltas without changing stored events. |
| `ollama.py` | Checks whether `GEMMA_MODEL` is already loaded in Ollama and loads it before the timed ADK turn when needed. |
| `output_channels.py` | Parses and validates `--outputChannels`, resolves per-agent channel visibility, and validates agent names against the live agent tree. |
| `__init__.py` | Empty. Importing the package does not load `agent.py`, so `cli/__main__.py` can apply the warning filter before the agents are constructed. |
| `experimental_warnings.py` | Applies the `[EXPERIMENTAL]` `UserWarning` filter when `--hide-experimental-warnings` is passed. |

## Invocation Flow

For a normal one-shot prompt:

1. `cli/__main__.py` hides `[EXPERIMENTAL]` warnings when `--hide-experimental-warnings` is present, then imports `cli_config.py`. That import loads `agent.py`.
2. `cli/cli_config.py` parses arguments.
3. `resolve_log_directory` picks `--log-dir`, then `LLLM_LOG_DIR`, then `.devcontainer/lllm/.local_only/local_llm_journal`.
4. `AdkSession.open` creates a session, or resumes `--session` through ADK's SQLite session service at `.devcontainer/lllm/.adk/session.db`. An unknown id fails before the model loads.
5. `ollama.ensure_model_loaded()` loads `GEMMA_MODEL` if Ollama is cold.
6. `AgentOutputVisibility` resolves the channel rules from `--outputChannels`.
7. `session.stream_events(prompt, ADK_SSE_RUN_CONFIG)` calls ADK:

   ```python
   runner.run_async(
       user_id=user_id,
       session_id=session_id,
       new_message=types.UserContent(prompt),
       run_config=RunConfig(streaming_mode=StreamingMode.SSE),
   )
   ```

8. `AdkEventRenderer.consume(event)` prints the selected parts of each ADK event.
9. `AdkEventRenderer.finish()` flushes final newlines, buffered text, or JSON. The runner already appended the turn's events to `.adk/session.db`, and that rewrite includes every CLI and `lllm web` message in `.devcontainer/lllm/.local_only/local_llm_journal/session_transcripts/<app>/<session id>/transcript.txt`. Stderr then prints `lllm session: <id>`.

## Agents

The current author names used by output filtering are:

| Agent | Role |
|-------|------|
| `lllm_default_agent` | Root coordinator (default). Use for general tasks, thinking, and allowing the local coordinator to manage the finer details of delegating to, verifying, and redirecting `browser_agent` and `files_agent`. Root answers are printed unlabeled on stdout by default. |
| `browser_agent` | Browser specialist (`--agent=browser_agent`). Use for direct orders over the devcontainer Chrome browser via Chrome DevTools tools. |
| `files_agent` | File specialist (`--agent=files_agent`). Use for direct orders over workspace and container files (list, search, read, edit, write). |

Sub-agent requests are treated as the callee's `prompt`. For example, a root
tool call to `files_agent` with a `request` argument is rendered as a
`files_agent` prompt, not as a root `tool_calls` line.

## CLI Options

| Option | Behavior |
|--------|----------|
| `query ...` | Runs one prompt and exits. With no query, `lllm` starts a REPL until `exit`, `quit`, EOF, or ctrl+c. |
| `--agent AGENT` | Runs a specific agent from the composed tree (`lllm_default_agent`, `browser_agent`, or `files_agent`) as the root agent for the session. Sub-agents configured as `single_turn` are cloned in `chat` mode when invoked directly. Omitting `--agent` selects `lllm_default_agent`. |
| `--outputChannels JSON` | Selects which information is printed for each agent. See below. |
| `--stderr` | Sends trace information to stderr while the root answer remains on stdout. Trace information includes thinking, tool lines, sub-agent prompts, and sub-agent responses. Ignored by `--json`. |
| `--no-stream` | Buffers selected text and prints the turn when ADK finishes. Useful for cleaner captured output, less useful for observing a long run. |
| `--json` | Prints one JSON object on stdout for the selected channels. This buffers until the turn finishes and ignores the stderr split. |
| `--timeout SECONDS` | Times out the ADK turn after this many seconds and exits 124. Model preload happens before this timer. |
| `--hide-experimental-warnings` | Hides ADK `UserWarning`s whose text starts with `[EXPERIMENTAL]`. Off by default, so those warnings are printed unless this flag is passed. The CLI applies the filter before it imports the agents. |
| `--log-dir DIR` | Directory for `session_transcripts/<app>/<session id>/transcript.txt`. Overrides `LLLM_LOG_DIR`. When both are unset, the directory is `.devcontainer/lllm/.local_only/local_llm_journal`. `lllm web` uses `LLLM_LOG_DIR` or that same default. |
| `--session ID` | Continues the ADK session in `.devcontainer/lllm/.adk/session.db`. `lllm web` uses that same file. Use the same `--agent` as the run that printed `lllm session: <id>`, and pick that same app name in the web UI. |

## Logs and sessions

Each session has one transcript, `.devcontainer/lllm/.local_only/local_llm_journal/session_transcripts/<app>/<session id>/transcript.txt`, unless `--log-dir` or `LLLM_LOG_DIR` selects another directory. It is rewritten from `.devcontainer/lllm/.adk/session.db` after every stored event, whether that event came from the CLI or `lllm web`. `lllm web` lists three apps: `lllm_default_agent`, `lllm_browser_agent`, and `lllm_files_agent`. A coordinator session appears under `lllm_default_agent`. A `lllm --agent=browser_agent` session appears under `lllm_browser_agent`. Pick that app, then that session id.

A follow-up passes `--session` and the same `--agent`. When the coordinator delegates to a specialist, that work stays on the coordinator session. Direct `--agent` chats are separate app rows.

Exit codes:
- `0`: Turn completed normally.
- `75`: Turn stopped early because the root agent hit a context limit, repeated the same tool cycle without new information, or entered a token-repetition loop.
- `124`: Turn exceeded `--timeout`.
- `130`: Interrupted with ctrl+c after closing the ADK runner.

## `--outputChannels`

`--outputChannels` is one shell-quoted JSON object. It changes terminal
presentation only; it does not change ADK, the model request, tool availability,
or sub-agent delegation.

Top-level keys:

| Key | Meaning |
|-----|---------|
| `defaults` | Channel overrides for every agent, including the root. |
| `sub_agent_defaults` | Channel overrides for agents under the root. Applies after `defaults`. |
| `agent_overrides` | List of targeted overrides. Each entry has `target_agents` plus channel booleans. Later entries win for keys they set. |

Channel keys:

| Channel | Meaning |
|---------|---------|
| `thinking` | Model thinking text. |
| `answer` | Final or streamed answer text. Root answers are unlabeled; sub-agent answers are labeled like `[files_agent response]`. |
| `tool_calls` | Tool names such as `[ReadFile]`, `[new_page]`, or `[take_snapshot]`. A sub-agent delegation is not printed here; it is the callee's `prompt`. |
| `tool_results` | Raw tool result payload text. This can be large. It is off by default. |
| `prompt` | User prompt for the root, or delegated request for a sub-agent. Root prompt is off by default; sub-agent prompts are on by default. |

Built-in defaults:

| Agent group | `thinking` | `answer` | `tool_calls` | `tool_results` | `prompt` |
|-------------|------------|----------|--------------|----------------|----------|
| Root agent | true | true | true | false | false |
| Sub-agents | true | true | true | false | true |

Resolution order:

1. Built-in root defaults.
2. Built-in sub-agent prompt default, for sub-agents only.
3. User `defaults`.
4. User `sub_agent_defaults`, for sub-agents only.
5. User `agent_overrides`, in list order.

Omitted keys keep the value from the layer below. Values must be JSON booleans
`true` or `false`, not strings like `"true"`.

### Examples

Hide thinking everywhere:

```sh
lllm --outputChannels='{"defaults":{"thinking":false}}' "Summarize example.com."
```

Show only the root answer:

```sh
lllm --outputChannels='{"defaults":{"thinking":false,"answer":false,"tool_calls":false,"tool_results":false,"prompt":false},"agent_overrides":[{"target_agents":["lllm_default_agent"],"answer":true}]}' "Visit example.com and report the title."
```

Hide sub-agent tool names but show raw file results:

```sh
lllm --outputChannels='{"sub_agent_defaults":{"tool_calls":false},"agent_overrides":[{"target_agents":["files_agent"],"tool_results":true}]}' "Read the first line of /workspaces/README.md."
```

Send trace information to stderr so stdout only contains the root answer:

```sh
lllm --stderr "Visit example.com and report the title."
```

Emit JSON for selected channels:

```sh
lllm --json --outputChannels='{"defaults":{"thinking":false},"sub_agent_defaults":{"tool_results":true}}' "Read the first line of /workspaces/README.md."
```

Invalid examples fail before a model call:

```sh
lllm --outputChannels='{"defaults":{"prompt":"true"}}' "ping"
lllm --outputChannels='{"agent_overrides":[{"target_agents":["file_agent"],"answer":true}]}' "ping"
```

The first fails because `"true"` is a string, not a JSON boolean. The second
fails because the live agent name is `files_agent`.

## Output Labels

Common terminal labels:

| Label | Meaning |
|-------|---------|
| `[files_agent]` | Delegated request sent to `files_agent`. |
| `[files_agent response]` | Answer produced by `files_agent`. |
| `[browser_agent thinking]` | Thinking text authored by `browser_agent`. |
| `[ReadFile]` | Tool call name. |
| `[ReadFile result]` | Tool result text when `tool_results` is enabled. |
| `[list_pages repair_truncated_utf8 1 encoded_callback_token 2 result]` | Tool result header annotated with the number of truncated URLs repaired and page addresses replaced with callback tokens. |
| `[lllm_default_agent prompt]` | Root user prompt when root `prompt` is enabled. |

The root answer is intentionally unlabeled so command substitution and piping can
consume it without stripping a prefix.

## Callback Tokens & Tool Result Rewriting

To keep long URLs and large text blocks from exhausting local model context windows
or getting corrupted when copied between agents, `tools/callback_tokens.py` and
`runtime_modifiers/tool_results.py` manage per-turn placeholders written as:

```text
[encoded_callback_token <number>_<timestamp>]
```

- **Automatic URL rewriting (`runtime_modifiers/tool_results.py`)**: Before tool results reach the
  model or terminal transcript, any percent-encoded URL cut off mid-UTF-8
  character is trimmed and marked with `[this URL was truncated]`. In `list_pages`
  results, URLs of 20 characters or more are stored in the turn's token map and
  replaced with `[encoded_callback_token <number>_<timestamp>]`.
- **Agent-initiated storage (`tools/callback_tokens.py`)**: Every agent has four tools:
  - `store_callback_token(text, note="", description="")`: Stores text >= 20
    characters (up to a 10 MB per-turn limit) and returns its token. Identical
    text reuses the existing token ID.
  - `preview_callback_token(id)`: Returns `first_20_characters`,
    `last_20_characters`, `character_count`, `note`, and `description` so agents
    can identify a token without loading its full text into context.
  - `list_stored_callback_tokens()`: Lists all stored token IDs and descriptions
    for the turn.
  - `recall_callback_token(id)`: Returns the full stored text when an agent
    explicitly needs to read it.
- **Automatic expansion**: Agents pass tokens unmodified in tool arguments,
  sub-agent handoffs, and final answers. `prepare_tool_arguments` automatically
  expands tokens inside tool arguments before execution (except for the four
  callback-token tools themselves), and `cli/output_writer.py` expands tokens in the
  active root agent's answer stream while keeping sub-agent trace outputs compact.

The web wrapper accepts ADK's `sessionId` request field and the older
`session_id` spelling. Live SSE output is framed before UTF-8/JSON decoding;
HTTP chunks may split a record, and model text deltas may split a placeholder.
Only possible placeholder suffixes are held, separately for each message,
invocation, author, branch, text part, and thought/answer channel. Final full
events are expanded independently of partial deltas. Ordinary text, event
metadata, and heartbeat records continue streaming. Unfinished or unknown
references remain literal at completion. A missing token refreshes the session
lookup so values stored by another runner task/process are visible immediately.
Session GET and nonstreaming `/run` JSON output also expand displayed values;
binary or encoded responses pass through. Persisted events remain tokenized.

## Turn Guards & Context Policy

`runtime_modifiers/turn_guards.py` wires ADK's `before_model_callback`, `after_model_callback`, and
`before_tool_callback` on every agent:

- **Context budget (`guard_model_request`)**: Estimates prompt tokens, budgeting
  conservatively for dense URLs/identifiers and non-ASCII text, and calibrates
  later requests against each agent's observed provider token usage. It reserves
  a quarter of the window for responses. When a request exceeds the target
  budget, it preserves the shared system instruction, instruction-marked role
  messages (including ADK's preamble), and the entire current user request.
  Earlier user requests and their context, observed progress, and the current
  work/purpose are summarized with bounded extracts, using at most one eighth
  of the effective context window. Recent context spans at most three user
  requests, including the protected current request; the additional tail uses
  at most one quarter of the window. These caps shrink when protected content
  and tool schemas leave less room. Tool calls and their results are retained
  together; oversized tail payloads may be shortened. Saved session content
  stays unchanged. If protected content cannot fit, tool declarations are
  removed before trying again; if it still cannot fit, the turn stops with an
  explicit context-full notice instead of truncating the user request or role.
- **Stall detection (`guard_model_request`)**: Fingerprints tool call/result
  pairs and stops tool use (`TURN_OUTCOME_STALLED`) if the agent repeats the same
  1-to-4 step cycle three times consecutively.
- **Repetition & thought-only recovery (`guard_model_response`)**: Clips
  generated-token repetition loops at the tail of a response
  (`TURN_OUTCOME_REPETITION`) and surfaces a summary of recent `<thought>` text
  if a model stops without emitting either a visible answer or a tool call.

## Model Loading

The command reads `GEMMA_MODEL`, `OLLAMA_HOST`, and `OLLAMA_KEEP_ALIVE` from the
environment. If `GEMMA_MODEL` is not already listed by Ollama's `/api/ps`,
`ollama.py` sends a small `/api/generate` request before the ADK turn starts and
prints:

```text
lllm: loading <model>
```

This preload is outside `--timeout`, because a cold model can spend a long time
loading weights before producing any ADK events.

## Development Notes

- Keep `agent.py` focused on the ADK app definition (models, tools, instructions,
  and sub-agent composition).
- Keep tool-result sanitization in `runtime_modifiers/tool_results.py`, context/stall/repetition
  guards in `runtime_modifiers/turn_guards.py`, and token storage/expansion in `tools/callback_tokens.py`.
- Output policy belongs in `output_channels.py` and `cli/output_writer.py`.
- Keep ADK runtime calls visible in `adk_runtime.py`; avoid hiding
  `runner.run_async(...)` behind additional layers unless there is a clear need.
- Add new output channels by updating `CHANNEL_NAMES`, defaults, renderer
  collection, text rendering, and JSON rendering together.
- Validate new agent-targeted options against the live agent tree so typos fail
  before the model starts.
